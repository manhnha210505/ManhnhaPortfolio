# Persona: Owner (ManhNha)

## Who this is
ManhNha, reviewing the site as its own primary stakeholder — not a persona for a third party. This file is a self-check reference: a way to audit whether the finished site actually serves the goals set out in `foundation/ProjectVision.md`, rather than drifting toward "impressive-looking but off-target" during implementation.

## Review checklist (use this when evaluating any milestone/build)
- [ ] Does the first viewport communicate "Data Science engineer," not "generic web developer"? (`foundation/TechnicalIdentity.md`)
- [ ] Are the four confident skill areas — DS, ML, Data Viz, MLOps — clearly visible and not diluted by an overly long, flat skills list?
- [ ] Does the Image Captioning project (or whichever projects are live) tell an honest story — team context disclosed, specific personal contribution stated, real numbers shown, limitations included? (`branding/Storytelling.md`, `profiles/HiringManager.md`, `profiles/TechLead.md`)
- [ ] Would a recruiter reading for 15 seconds get the right first impression? (`profiles/Recruiter.md`)
- [ ] Would a Tech Lead who reads the actual GitHub repo find the site's framing consistent with what they read there? (`profiles/TechLead.md`)
- [ ] Is the visual execution actually distinctive, or has it drifted into the generic "dark + single accent + Apple/Linear inspiration" pattern flagged in `design/DesignPhilosophy.md`?
- [ ] Is the signature element (once chosen, per `foundation/ProductRequirements.md`) something that demonstrates real DS/ML skill, not just visual flair?

## When to use this
- At the end of each major implementation milestone (per `governance/DefinitionOfDone.md`), before considering a section "done."
- Before adding a new project to the Projects section — apply the same honesty/specificity bar used for Image Captioning.
- Before any public launch/share of the site — a final full read-through against this checklist, ideally after a few days away from the project for fresh eyes.

## Not a substitute for
External feedback. This checklist catches self-consistency and honesty gaps; it does not replace getting a real recruiter, hiring manager, or tech lead to actually look at the site before treating it as finished.
