# Typography

## Direction
Large type, confident spacing, strong hierarchy — per `DesignPhilosophy.md`. As of the Mecha Typography direction (`design/MechaTypographySystem.md`), typeface selection now has a constraint, not just an open choice:

- **Display/accent typeface** (angular, industrial/mecha-influenced) — used ONLY for: section index numbers (`01/06`), status tags (`[ACTIVE]`), and optionally the Hero headline at large display size. Evaluate options with sharp geometric cuts and strong numeral design (many "mecha fonts" are display/logotype faces, not full text families — confirm the chosen one has the specific glyphs needed: digits, brackets, uppercase Latin — before committing).
- **Body/UI typeface** — a clean, highly legible sans (or a technical mono for labels/data) completely separate from the display face. Body copy, navigation, and all Skills/Projects/About text must stay maximally readable — this is non-negotiable per the medium-application constraint in `MechaTypographySystem.md`. Do not let the mecha aesthetic bleed into paragraph text.
- **Mono typeface** — for status tags, section numbers, data values, and code-adjacent content — reinforces the "technical readout" motif and doubles as the DS/engineering identity signal noted in the original direction below.

## Scale
Define a modular type scale (e.g. 1.25–1.333 ratio) covering at minimum:
- Display (Hero headline)
- H1–H3 (section headings)
- Body (large, default, small)
- Caption/label (metadata, tags, nav)
- Mono (code snippets, technical labels, data values — reinforces the DS/engineering identity)

## Rhythm
- Consistent line-height per tier (tighter for display, more relaxed for body).
- Consistent vertical rhythm tied to the same spacing scale used in `LayoutSystem.md` — headings and body copy should land on the same baseline logic across sections.
