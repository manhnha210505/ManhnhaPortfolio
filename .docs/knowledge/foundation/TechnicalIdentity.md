# Technical Identity

## Who this site represents
A **Data Science engineer** whose scope spans the full lifecycle: statistics and analysis → model development (ML/DL) → productionization (MLOps) → the backend/cloud infrastructure that serves it. The site must make this end-to-end range legible, not just "knows Python and pandas."

## Competency taxonomy (must be visibly represented)
- Data Science & Statistics
- Machine Learning
- Deep Learning
- Artificial Intelligence
- Data Analysis
- Data Visualization
- MLOps
- Backend Development
- Cloud Technologies
- Modern Full-stack Development

These map directly into `Skills` section content and should also surface implicitly through **how** the site is built (e.g., the signature element itself should demonstrate data visualization or data storytelling skill, not just describe it).

## How identity is communicated
1. **Explicitly** — Skills section, About narrative, resume/CV artifacts.
2. **Implicitly** — the engineering quality of the site (performance, motion precision, code standards) is itself a proof point of full-stack + production competence.
3. **Through case studies** — Projects section frames work as problem → approach → impact, the way a DS engineer would frame a project retro, not as a feature list.

## Tone balance
Precision and creativity are both required — see `branding/VoiceAndTone.md`. Never let creative flourish obscure technical accuracy (e.g., don't use vague marketing language like "leveraging cutting-edge AI" without a concrete claim behind it).
